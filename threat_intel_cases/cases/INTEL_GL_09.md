# INTEL_GL_09 · Snowblind：利用 Linux 内核 `seccomp` 系统调用过滤隐身绕过无障碍反检测

- **来源类型**：`[Source C · 公开威胁情报 / 警方通报 / 安全实验室博客]`
- **地区与活跃期**：东南亚及全球金融目标（2024）
- **隐蔽度分级**：`Level 3 · 跨页隐蔽协同与感知劫持型`
- **为何首启/离线动态易遗漏**：内核级 `seccomp` 拦截反篡改与无障碍存活检查
- **关联新扩充行为模式编号**：`EVADE_08`

## 1. 伪装外衣与带外接触通道
- **伪装形态**：重打包/注入目标金融 App 或配套侧载恶意 APK
- **带外接触通道**：钓鱼站点侧载与社工诱导
- **应用内界面特征**：利用 Linux 原生安全机制 `seccomp`（Secure Computing Mode）反向对抗移动安全 SDK：在银行 App 执行反重打包校验或查询活跃 `AccessibilityService` 之前拦截系统调用并返回伪造的干净结果

## 2. 真实诱骗话术与剧本摘录
- 「诱导授予无障碍权限后，通过 `seccomp` 过滤器截断银行 App 读取 `/proc` 与校验无障碍服务列表的系统调用」

## 3. 完整攻击杀伤链
- 1. 诱导用户侧载并授予无障碍权限
- 2. 注入原生库安装 `seccomp` BPF 过滤器拦截敏感系统调用（如 `openat`）
- 3. 绕过银行 App 的反篡改和无障碍检测后，静默利用无障碍窃取凭证并绕过生物识别/二次验证

## 4. 端侧 UTG 与跨信道可观测特征
- 说明单纯依赖目标银行 App 自身事后检测无障碍已不够，必须在**操作系统授信入口（系统无障碍设置页 UTG 锚点）**提前拦截恶意诱骗授权！

## 5. 鸿蒙端侧防御与检测映射
- 强化 OS 系统级无障碍授权前 UTG 拦截，而非把防御压力转嫁给银行 App 自身运行时检测
