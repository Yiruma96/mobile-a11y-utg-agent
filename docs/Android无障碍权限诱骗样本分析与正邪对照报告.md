## 二、五条正交端到端 UTG 诱导路径原型（队列 A `n = 224`）

严格剔除 96 例加密包与 11 例非无障碍误入包及 17 例零引导潜伏包后，全部 **224 例静态可观测主动诱骗样本**清晰收敛为五条互斥正交的端到端页面流转原型：

1. **原型 1 · 冷启动模态阻断与心理胁迫（`92/224 = 41.1%`）**
   - **典型家族**：`EventBot`、`Brata`、`Cerberus`、`Asacub`、`Lucy`、`Vultur`、`GodFather`、`BrasDex`、`Hydra`、`Riltok`。
   - **实证机制**：冷启动 0 业务步即弹不可取消原生 Dialog/Activity；涵盖假系统/浏览器更新（`EventBot` *Flash Update*、`Brata` *WhatsApp 2.5*）、运行故障恐吓（`Asacub` 先弹“应用已删除”自禁图标再延时 78s 每 10s 弹同形字系统故障）、假反诈（`Vultur`）、30 换行挤出系统警告（`Lucy`）、以及取消键绑定同一跳转监听的「假取消」（`BrasDex`）。
2. **原型 2 · 多语种 WebView 教学与高仿系统设置接力（`73/224 = 32.6%`）**
   - **典型家族**：`Sova`、`Escobar`、`cebruser`、`SpyMax`、`Hook`、`Ermac`、`BingoMod`、`TrickMo`、`Copybara`、`Octo`、`TangleBot`。
   - **实证机制**：使用本地离线或 C2 动态下发 HTML WebView 展示多语种图文分步教学（如 `Sova chrome.html`、`cebruser` 40+ 语种），或直接渲染高仿系统「已下载的服务」开关列表（`Escobar`、`SpyMax`），点击假开关/按钮经 JS 桥直跳真设置（`Escobar` 在跳前先 `finishAndRemoveTask()` 擦除前页痕迹）。
3. **原型 3 · 工具功能按需埋点与警告消解 / 跳后压栈偷袭（`41/224 = 18.3%`）**
   - **典型家族**：`SharkBot`、`solid/Easy Cleaner`、`Click`、`TOASTAMIGO`、`ewind`、`hiddad`、`Xavier`(遮罩版)、`Joker`、`GoldDigger`。
   - **实证机制**：最易与良性清理/工具混淆的灰区——先提供真实主界面与功能入口，点击功能后弹窗，通过**显式教唆忽视系统隐私警告**（`SharkBot` *"You will have to accept Android system warinings"*、`Easy Cleaner` *"You can have the privacy warning ignored"*）或在跳入系统设置页 **100ms–1s 内叠加全屏半透明指引遮罩/GIF**（`Click` 100ms、`Xavier` 170ms、`SharkBot/TOASTAMIGO` 800ms）驱动用户打开开关。
4. **原型 4 · 零应用内引导直跳与居中 Toast 轮询（`14/224 = 6.2%`）**
   - **典型家族**：`RuMMS`、`Anubis`、`AnubisDropper`、`Svpeng`、`Oscorp`、`Coper`、`SpyNote`(无 UI 版)、`Ztorg`。
   - **实证机制**：无可见应用主界面（或透明 1px 启动页直接 `finish()`），由后台服务每 0.2s–10s 轮询并强制跳转系统无障碍设置页，配合一条屏幕居中 `Toast`（`RuMMS`、`Anubis`）或仅靠系统列表里的 `android:description`（`Ztorg`）完成诱骗。
5. **原型 5 · 一阶段假重装 Dropper 投递二阶段（`4/224 = 1.8%`，外加队列 C 嵌包变种）**
   - **典型家族**：`Chameleon`、`GodFather`(嵌包版)、`Crocodilus`、`TeaBot`。
   - **实证机制**：外层 APK 不声明无障碍，先以假登录报错诱点 `Reinstall` 经 `PackageInstaller.Session` 绕过 Android 13 受限设置投递内嵌二阶段 APK，待二阶段启动后再转入原型 1/2。

## 三、70 款开源良性并置对照与「对称口径」正邪分水岭

### 1. 静态权限与能力位为何必然高误报？
将 472 个近期恶意样本与 70 款开源良性工具按完整静态配置并置：
- **全局通配监听（未限 `packageNames`）**：开源良性 **88.6%（62/70）** 与近期恶意 **90.7%** 几乎持平；
- **`canRetrieveWindowContent`**：良性 **47.1%（33/70）**；**`QUERY_ALL_PACKAGES`**：良性 **50.0%（35/70）**；**`SYSTEM_ALERT_WINDOW`**：良性 **37.1%（26/70）**；**`canPerformGestures`**：良性 **25.7%（18/70）**。

### 2. 三大实测良性误报雷区（修正 V1 错误判据！）
- **雷区 ① Android 13+ 受限设置教学**：**24.3%（17/70）** 侧载开源良性应用（`SD Maid SE`、`Nudge`、`Focus`、`GrayPause`、`Sefirah`、`Screenshot Tile` 等）合法教学「应用信息 → 右上角三点菜单 → 允许受限设置」——**严禁将其作为判恶规则**（仅用作提前预热锚点）；
- **雷区 ② 单用途首启向导**：**21.4%（15/70）** 良性工具冷启动/浅层即入权限向导；
- **雷区 ③ 隐私承诺文案**：**38.6%（27/70）** 良性应用主动使用“绝不收集数据/完全离线”承诺，须与恶性「**显式教唆忽视系统安全警告**（`31.2% vs 0%`）」严格区分；
- **工程细节雷区**：动态实测证实良性 `Screenshot Tile` 跳设置页后亦弹普通底部 `Toast`（故压栈规则须锁定异源浮窗/透明 Activity 而非底部 Toast），且其 XML 描述含单零宽符 `U+200C`、`SuperFreezZ` 合法描述含 8 个段落换行。

### 3. 最高重叠灰区正邪对照：`SharkBot / Easy Cleaner` vs `SD Maid SE / SuperFreezZ`
| 事中可观测维度 | 恶意清理伪装（`SharkBot` / `Easy Cleaner`） | 开源合法清理（`SD Maid SE` / `SuperFreezZ`） |
| --- | --- | --- |
| **身份与品牌署名** | `LiteCleaner M` 文案混称 `Clean Master`；`Easy Cleaner` 混用 `Dr. Security` | 应用名、卡片说明与系统无障碍列表 100% 如实一致 |
| **系统警告态度（`t0-ε`）** | 显式教唆忽视系统隐私/安全警告 | 透明披露自动点击范围与随时撤销权，绝不教唆忽视警告 |
| **拒权可降级性（骨架环缓）** | 无跳过替代，返回后 500ms 轮询重拉或交替压栈 | 显式拒绝按钮 + ADB/Root/手动冻结替代，返回后 0 自动重拉 |
| **跳后窗口行为（WMS）** | 跳设置页后 800ms–1s 叠加半透明指引层 | 干净单次原生跳转（`SuperFreezZ` 将监听包锁死于 `com.android.settings`） |

## 四、面向「事中化 + 低功耗」的免全时 Layout 架构与三层信号体系

### 单一核心思想：**生命周期限域的跳前单次捕获与双阶段事中核验**
正面回应移动端功耗与时序不对称的核心矛盾——**绝不在日常运行期对每次页面切换做全量 Layout 抓取**：

1. **安装态限域门控**：仅对「非商店侧载/企业分发 ∧ 声明无障碍能力 ∧ 当前未授权」的极少数目标应用激活；其余 99.9% 应用零监控、零功耗。
2. **常态零 Layout 骨架环缓（< 2 KB 内存，功耗 ≈ 0）**：复用 AMS/WMS 既有生命周期与输入分发元数据，维护最近 8 帧 `(ability, windowType, flags, lastTouchTime)`，零 Layout 遍历即刻产出导航深度 d、是否触摸驱动跳转、跳后 0–2 s 异源浮窗压栈与拒权 30 s 自动重拉循环。
3. **跳前单次同步快照（`t0 - ε`）**：拦截 `startAbility` / `startActivity` 指向无障碍设置页（或应用详情页）的瞬间，**在设置页覆盖屏幕前同步抓取 1 帧当前前台诱导窗口 + 最后点击控件文本**（针对 `Escobar` 类先 `finish()` 绕过，捕获 WMS/RenderService 切页销毁前的离场窗口缓存）。
4. **3–10 秒人工开关窗口异步裁决与事中拦截**：无障碍属 `manual_settings` 多步人工开启流程，利用用户从设置列表点到最终「允许」弹窗前的 3–10 秒人工耗时，异步完成话术语义、按需单帧 OCR（仅空文本大图，占队列 A 20.1%）、WMS 跳后浮窗检测与可选只读元数据核验，在最终确认弹窗处实现真正的**事中阻断或高风险强化提示**。

### 三层信号可观测分工与对称覆盖率（队列 A `n=224` vs 良性 `n=70`）
- **层 1A · 跳前 `t0-ε` 纯 UTG 单帧（零外部元数据）**：捕获恐吓话术（59.8%）、教唆忽视警告（31.2%）、假设置页（8.5%）、字面名称冲突（20.5%）、空白/连空行/同形字（14.3%），单层覆盖队列 A **173/224（77.2%）**，开源良性 **0/70**。
- **层 1B · 无 Layout 骨架环缓与 WMS 窗口事件**：补齐拒权严格死循环（75.9%）与跳后压栈遮罩（31.7%），层 1A+1B 联合覆盖队列 A **212/224（94.6%）**（含队列 B **90.0%**），开源良性 **0/70**。
- **层 2 · 轻量系统只读元数据（零 EDR）**：引入包名/签名 × 知名品牌白名单（31.2%）、多 `activity-alias`（25.0%）与服务静态描述/声明，总覆盖队列 A **216/224（96.4%）**（含队列 B **94.2%**），开源良性 **0/70**。

### 诚实边界与有效性威胁（Threats to Validity）
1. **温和外壳与泛用无文案裸跳盲区**：队列 A 仍有 **8 例**未命中（含 2 例温和桌面美化 `Xavier` 及无文案泛用名裸跳），队列 B 另有 **17 例**静默潜伏/Xposed 不触发应用内跳转，需应用市场准入、签名信誉与系统完整性校验协同兜底。
2. **静态标签评估偏差与动态盲测缺口**：上述 418 应用分析基于静态代码逆向且批量提示词含应用类别背景；真正无泄露评测须在正在构建的断网动态 GUI-Owl UTG 集（含 96 例队列 C 加密样本解包后轨迹）上执行盲测。
3. **良性样本生态偏差**：70 款良性全为 F-Droid/GitHub 英文开源工具，须增补 15–20 款国内主流商业良性无障碍应用复测误报。

## 五、核心顶会文献谱系（8 篇已全部 PDF 核验入库 `llm_wiki`）

1. **Cloak and Dagger (IEEE S&P'17, Fratantonio et al.)**：*UI 反馈闭环攻击* — 揭示悬浮窗与无障碍双权限协同闭合 UI 反馈闭环的 12 类攻击（20 人实验 0/20 察觉），推动 Android 8+ 封堵设置页覆盖点击。
2. **Kindness Is a Risky Business (USENIX RAID'19, Diao et al.)**：*无障碍生态实证测量* — 测绘 91,605 款应用发现 337 款无障碍应用中仅 3.2% 面向残障，提出以专用安全 API（如 `AutofillService`）疏导合法需求。
3. **A11y and Privacy (USENIX Security'21, Huang et al.)**：*最小权限数据流约束* — 证实静态配置与 API 边界观察难分正邪，提出系统侧最小权限沙箱模块与不透明句柄（需改造 OS 框架，且未触及授权前社工诱导）。
4. **DVa (USENIX Security'24, Xu et al.)**：*授权后动态取证归因* — 分析 9,850 个无障碍恶意样本，证实 92% 具备防撤权机制、Android 13 与数据流防御下仍留存 67% 与 40% 滥用（同脉络 `SOMBRA` CCS'25 进一步揭示浏览器 AOM 侧泄露），证明事后防守极难闭合。
5. **AppContext (ICSE'15, Yang et al.)**：*安全敏感行为上下文分类* — 提出以「激活事件（UI/系统/硬件）+ 环境上下文因子」区分恶意与良性敏感行为（846 应用级 P=87.7%、R=95.0%，平均耗时 647s/应用），直接启发本文在零 Layout 骨架环缓中区分触摸驱动 vs 后台/无交互自动跳转。
6. **Can Systems Explain Permissions Better? (USENIX Security'21, Shen et al.)**：*运行时权限认知与决策干预* — 基于 4,636 名真实用户与 1,559 份问卷证明仅 6.1% 用户能准确推断权限组范围，54.7% 误把开发者文案当系统提示，且**负面风险提示在系统确认页最能扭转误授权**——直接支撑本文在 3–10s 人工开关确认窗口执行事中拦截。
7. **The Power of Words (NDSS'25, Elbitar et al.)**：*权限理由措辞框架测量* — 量化 720 条权限理由与 960 人实验，证明隐私承诺（`OR=1.43`）与可撤销措辞（`OR=1.28`）显著拉高授权率，解释恶意清理外壳为何高频伪造隐私承诺。
8. **AppRay (ACM TOSEM'26, Chen et al.)**：*跨页欺骗界面检测* — 以连续 UI 序列与跨页规则检出 16 类商业暗黑模式（Micro F1 = 0.89），启发跨页拓扑建模，但属离线重型探索且未建模高危无障碍授权、功耗约束与良性高重叠豁免。
