## 1. 一句话核心结论

- **核心申请方式**：在 Power Boost 功能页点击按钮时跳转系统无障碍列表，并在 170ms 后向系统设置页叠加全屏半透明遮罩卡片，用图示分两步教用户找到并打开『Battery Saver』无障碍开关，获权后再以同样方式引导授权 WRITE_SETTINGS，并由无障碍服务在设置页自动点击『强行停止』及确认框。

## 5. 让用户完成开启的具体机制与拒权反馈

- **触发时机（Trigger Timing）**：`user_feature_on_demand`
- **是否提供取消/跳过出口**：`False`
- **拒权或返回后的反馈回路**：无强制循环：未授权时 i() 直接返回 false，powerBoost 不执行清理；用户从系统设置返回后 onResume 仅刷新进程列表（g() → fr AsyncTask），需再次点击『Power Boost』才会重新跳转设置并重新压遮罩；遮罩可经『Got it』(ex/ey.onClick) 关闭，onDestroy 后 500ms 由 eu.run 移除视图。
- **遮罩叠层 / 高仿系统设置页**：是，叠放全屏半透明引导遮罩（非高仿系统页）：跳转 ACCESSIBILITY_SETTINGS 后 170ms 由 ew.run → j() 以 WindowManager.addView 加入 res/layout/view_window_setting.xml，type=2032/2002、flags|=8（FLAG_NOT_FOCUSABLE）、宽高 -1、背景 @color/mask_bg，中央白卡片用绿色高亮框 + boost_arrow/ic_button_on 图片模拟系统开关位置与状态，需 WRITE_SETTINGS 时由 k() 以同一布局覆盖在 MANAGE_WRITE_SETTINGS 页上。
- **Android 13+ 受限设置（Restricted Settings）应对**：无。应用 targetSdkVersion=20（2017 年样本），未出现『应用详情页右上角菜单 → 允许受限设置』或 Session 安装器绕过引导；受限授权引导仅限 ACCESSIBILITY_SETTINGS 与 MANAGE_WRITE_SETTINGS 两处跳转 + 遮罩图示。
- **获权后即时行为与防撤权机制**：无阻止撤权行为（未监听设置页用 GLOBAL_ACTION_BACK/HOME 阻挠关闭开关）。但获权后存在两项越权代操作：① onServiceConnected() 中 b() 通过 getRunningTasks(1) 判断栈顶为本包时 startActivity(ForceActivity) 将用户拉回应用；② onAccessibilityEvent 仅在 com.android.settings 窗口内检索 force_stop/common_force_stop/right_button/left_button 并 performAction(16)，对 Dialog 类节点延迟 1000ms 后点击 dlg_ok/yes/android:id/button1，自动代替用户点击『强行停止』与系统二次确认框。
- **良性降级 / 替代方案**：部分具备：拒权后仅 Power Boost 功能不可用，其余省电/降温/白名单等功能不受影响，无弹窗骚扰或强制重试；但未提供手动清理或 ADB 等替代路径说明。

## 分析结论要点

**可见性**：`static_visibility = clear`。无障碍申请流程全部在 `classes.dex` 与 `res/` 内静态可见，无加壳、无密文载荷、无远端 HTML 参与（`assets/` 仅 `license.html`、`policy.html`，与本流程无关）。

**核心机制（纯运行期 UTG 视角）**
1. **冷启动不弹**：入口是 `SplashActivity`→`MainActivity`，无障碍申请完全由**业务功能触发**——用户在 Power Boost 页点「Power Boost」按钮，或动画结束回调拉起 `ForceActivity`。
2. **功能页 → 权限判定 → 跳系统设置**：`ForceActivity.powerBoost()` → `i()`，用 `Settings.Secure.enabled_accessibility_services` 判断 `包名/PowerBoostService` 是否已启用；未启用则 `startActivity("android.settings.ACCESSIBILITY_SETTINGS")`。
3. **170ms 后压栈全屏引导遮罩**：`Handler().postDelayed(new ew(this), 170L)` → `j()` 通过 `WindowManager.addView` 叠加 `res/layout/view_window_setting.xml`（`type=2002/2032`、`FLAG_NOT_FOCUSABLE`、宽高 `-1` 全屏、`@color/mask_bg` 半透明底 + 白卡片），恰好覆盖在系统无障碍列表之上，用图 + 文字分两步教用户找到并打开 “Battery Saver” 开关。
4. **二级引导**：无障碍已开但 `WRITE_SETTINGS` 未授权时，`k()` 用同一布局再压一次遮罩，并跳 `android.settings.action.MANAGE_WRITE_SETTINGS`（`jd.a()`，SDK≥23）。
5. **拒权反馈**：无死循环重跳。`onResume` 只刷新进程列表；用户返回后需再点按钮才会重新跳转，`i()` 返回 false 时功能静默不执行。
6. **获权后**：`PowerBoostService.onServiceConnected()` 若检测到栈顶仍是本应用，则 `startActivity(ForceActivity)` 把用户带回应用继续；`onAccessibilityEvent` 仅监听 `com.android.settings` 的 `typeWindowStateChanged`，用 `findAccessibilityNodeInfosByText("force_stop"/"common_force_stop")` 或 `com.android.settings:id/right_button` 执行 `ACTION_CLICK`，对 Dialog 类节点延迟 1000ms 后点 `dlg_ok`/`yes`/`android:id/button1`——即在设置页自动点「强行停止」并自动确认系统二次确认框。

**伪装性**：显示名、无障碍服务标签、`android:description` 与真实行为基本一致（确实只针对设置页做停止应用），无空白挤出、同形字、多 `activity-alias`、伪造 `isAccessibilityTool`（targetSdk 20）。属于「透明说明 + 遮罩分步教学」型诱导，而非冒充系统安全组件。
