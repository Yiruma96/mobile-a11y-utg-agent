# 移动端诱导用户开启无障碍行为模式清单与低功耗事中 UTG 捕获指南（V3 清洗修正版）

> **实证与清洗口径（纠偏说明）**：基于 **1,769 个三源去噪核验无障碍 APK**（MalRadar 2014–2021 `1,227` + MalwareBazaar 2022–2026 `472` + 开源良性 `70`）及 **418 份「一应用一文件」代码级逆向报告**（[per_app_reports/INDEX.md](per_app_reports/INDEX.md)）。本版严格修正了初版存在的**加壳样本脑补标签污染、非无障碍误入噪声、LLM 真值提示泄露及良恶口径不对称**问题，将 348 份恶意逆向样本划分为四个互斥队列后再做对称统计：
> - **队列 A（静态可观测主动诱骗/跳转池，`n = 224`）**：MalRadar `134` + MalwareBazaar `90`，覆盖 `63` 个独立命名恶意家族——**本清单所有诱导模式占比与正邪对照的唯一合法恶意分母**；
> - **队列 B（零应用内引导潜伏 / Xposed / Root 提权池，`n = 17`）**：无任何应用内引导页与跳转，仅靠服务名伪装静待误点或 Xposed/Root 自授权（单独归类，不混入主动诱导）；
> - **队列 C（强加壳 / VMP / AES 密文遮蔽池，`n = 96`）**：静态不可还原引导链路（初版误将其中 `66` 例冷启动、`45` 例遮罩、`17` 例教唆忽视警告脑补标签混入统计，本版**全部剥离**，留待动态 GUI-Owl 采集验证）；
> - **队列 D（静态初筛误入的非无障碍样本，`n = 11`）**：经代码逆向证伪不含无障碍引导的样本（4 例 `HiddenAd` 后台广告、3 例 `Etinu` 输入法/广告、2 例 `Unattributed` 调试面板、1 例 `GhostClicker` 快捷方式、1 例 `meftadon` 空壳），**已剔除出有效分母**。

## 一、破局端侧功耗与事中化难题：为什么无需「每页切换都抓 Layout」？

### 1.1 与 ClickFix 的本质差异：时序不对称困境（Temporal Asymmetry Dilemma）

| 维度 | ClickFix（剪贴板/终端诱骗） | 移动端无障碍权限诱导（Accessibility Inducement） |
| --- | --- | --- |
| **诱导与触发的相对时序** | 触发事件（写入剪贴板）发生时，恶意网页**仍在屏幕前台** | 诱导界面（Dialog / WebView / 假设置）出现在**进入系统设置之前**；跳进系统设置后原诱导页已被切走甚至 `finish()` |
| **纯事后捕获的缺陷** | 单次触发即可抓到当前完整网页 | 等用户**事后**打开无障碍开关或已切入系统设置再抓，前置诱导画面已消失 |
| **朴素全时捕获的代价** | 无需全时监控 | 若对侧载应用**每次页面切换都做全量 Layout 树遍历**，CPU、IPC、内存与功耗开销均不可接受，且存在隐私合规负担 |
| **可利用的 OS 黄金窗口** | 复制到粘贴存在人类操作间隔 | 无障碍属 **`manual_settings` 多步人工开关**：跳进设置页到用户点进「已下载的应用 → 目标服务 → 打开开关 → 点系统二次确认允许」天然存在 **3–10 秒人工导航窗口** |

### 1.2 核心解法：生命周期限域的「无 Layout 骨架环缓 + 跳前单次同步快照 + 事中确认页拦截」

严格遵循 **零 EDR、零全时 Layout 轮询、事中（授权生效前）拦截** 约束，将检测拆分为四步极简低功耗状态机：

1. **安装态限域门控（99.9% 日常应用零开销）**：仅对同时满足「① 非应用市场侧载/企业分发；② 声明 `AccessibilityExtensionAbility` / `BIND_ACCESSIBILITY_SERVICE`；③ 当前无障碍权限处于**未授予**状态」的应用激活轻量监控；一旦授权完成或正常会话结束即自动解除。
2. **常态零 Layout 骨架环缓（AMS/WMS 元数据，功耗 ≈ 0）**：日常运行期**绝对不做任何 `dumpLayout` / 控件树序列化**；仅复用 OS 窗口/能力管理框架（AMS/WMS）原本就维护的极轻量元数据环缓（最近 K = 8 条记录，`< 2 KB` 内存）：`(timestamp, bundleName, abilityName, windowType, flags, lastUserTouchTime)`。仅靠这份零 Layout 骨架即可直接白拿：**业务导航深度 d、跳转是否由真实用户触摸驱动、跳后 0–2 s 是否有异源浮窗压栈、拒权返回 30 s 内是否无触摸自动重拉**。
3. **跳前单次同步快照（`t0 - ε` Pre-Transition Sync Snapshot — 事中核心抓手）**：当受限应用发起跳转 `ACCESSIBILITY_SETTINGS`（或 `APPLICATION_DETAILS_SETTINGS`）调用 `startAbility` / `startActivity` 的**同一毫秒（在系统设置页完成首帧切换、且前序诱导窗口被销毁之前）**，同步执行 **1 次** 前台窗口 Layout 快照 + 命中检测最后一次点击控件文本（专抓 `BrasDex` 类假取消键）。
   - **针对「先 `finish()` 再跳设置」对抗（如 `Escobar` / 透明启动页）**：复用 WMS/RenderService 切页动画销毁前的离场窗口缓存（Outgoing Window / TaskSnapshot），或仅对受限应用关闭 Dialog/WebView 时做 1 槽位纯文本摘要缓存（不落图、非普通页面切换不触发）。
4. **借用 3–10 秒人工开关窗口完成「事中异步裁决 + 最终确认弹窗拦截」**：跳前快照在 `< 30 ms` 内无感放行系统设置页；检测引擎在用户浏览设置列表的 **3–10 秒人工操作间隙**内异步完成话术语义、按需单帧 OCR（仅空文本大图触发）及 WMS 0–2 s 浮窗压栈观测；**在用户点击系统最终「允许开启无障碍」二次确认弹窗之前（真正的事中！）**输出裁决：高危则强告警/阻断确认，灰区未授权返回则保持骨架环缓观察 30 秒捕获拒权死循环。

## 四、70 款开源良性规律与「生态代表性偏差」警示

1. **开源良性 4 条共性正向规律**：① `70/70` 桌面名与系统服务名如实一致（允许品牌+功能后缀如 `RustDesk Input`）；② `0/70` 教唆忽视系统警告、拒权自动死循环或跳后异源压栈；③ `84.3% (59/70)` 提供免无障碍替代模式（ADB/Shizuku/Root/手动/仅观看）；④ 密码管理器 `KeePassDX` / `Keepass2Android` 新版已迁移至原生 `AutofillService`。
2. **三大已证实的误报雷区**：侧载受限设置教学（`24.3%`）、单用途首启引导向导（`20.0%`）、隐私承诺文案（`38.6%`）；此外还实测发现 **2 条工程细节雷区**：`Screenshot Tile` 跳入设置页后会弹普通底部 `Toast`（故不能把底部 Toast 当恶意遮罩），其 XML 描述首字符含翻译工具生成的 `U+200C`；`SuperFreezZ` 的合法长描述含 8 个段落换行（故换行挤出警告规则必须匹配**连续空行 ≥ 4** 而非总换行数）。
3. **必须正视的外部效度威胁（Benign Bias）**：当前 70 款良性 **100% 来自 F-Droid / IzzyOnDroid / GitHub 英文开源工具**（其中极简桌面双击锁屏就占 18 款），**尚未覆盖国内商业良性无障碍应用**（向日葵/ToDesk 远程协助、商业跳广告、自动化脚本、老人/家长守护等）。商业工具更常使用图文/动图引导、悬浮球指引与较强首启流程——**在补测商业/中文良性集前，绝不可宣称“全生态 0% 误报”**。
