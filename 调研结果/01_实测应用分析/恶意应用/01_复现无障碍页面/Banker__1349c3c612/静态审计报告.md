## 1. 一句话核心结论

- **核心申请方式**：该应用在冷启动 onCreate 中检测无障碍未启用后仅弹两个 Toast 就立刻跳系统无障碍设置页，无说明页、无取消，服务开启后自动连按最近任务关掉设置页、在悬浮窗/设置页自点开关自授权，并对卸载器与卸载提示连按 BACK 阻止撤权，同时用『追踪任意 WhatsApp 号码』的虚假定位器人设掩盖银行木马行为。
- **静态可见性说明**：本地 DEX 未加壳，冷启动跳转、拒权重跳、自点开关、按 BACK 撤权拦截、悬浮窗授权等全部逻辑静态可还原；但引导教学/落地页正文与覆盖层内容位于远端（https://bitsolution.info/?odjasijdaosi、http://braziliankings.ddns.net/renew、Config.urlUber/urlItc + load.php?hwid=），包内无 assets/HTML，故远端页面文字无法静态取证。
- **命中的行为模式标签**：`TRIG_COLD_START_BLOCK`（冷启动0步强阻断直弹授权）、`TRIG_BACKGROUND_OR_NOTIF_RELAUNCH`（后台服务/定时器/通知栏反复拉起授权页）、`CARRIER_NATIVE_DIALOG_OR_ACTIVITY`（原生弹窗(Dialog)或原生引导页(Activity)）、`CARRIER_WEBVIEW_REMOTE_URL`（远端下发HTML/WebView动态引导页）、`CARRIER_OVERLAY_MASK_OR_GUIDE`（悬浮窗/透明遮罩引导层）、`CARRIER_SYSTEM_A11Y_DESCRIPTION`（系统无障碍列表服务说明(android:description)）、`LURE_PRIVACY_GUARANTEE_CLAIM`（主动抛出「绝不收集隐私/安全可靠」承诺）、`LURE_UTILITY_CLEANER_DISGUISE`（合法清理/省电/工具外衣伪装）、`LURE_DISMISS_SYSTEM_WARNING`（显式教唆忽略/接受系统隐私与安全警告）、`COERCE_NO_SKIP_NON_CANCELABLE`（不可取消弹窗/无跳过出口/单一正向按钮）、`COERCE_REFUSAL_LOOP_RELAUNCH`（拒权或返回后死循环重拉无障碍设置页）、`COERCE_OVERLAY_STACK_ON_SETTINGS`（跳入系统设置页后短时压栈透明指引/遮罩窗）、`ID_SYSTEM_OR_BRAND_IMPERSONATION`（冒充系统组件/Google/大厂或银行品牌身份）

## 5. 让用户完成开启的具体机制与拒权反馈

- **触发时机（Trigger Timing）**：`cold_start_0_step`
- **是否提供取消/跳过出口**：`False`
- **拒权或返回后的反馈回路**：用户从系统无障碍页返回且未开启时，MainService.onCreate → a11yperms() 以 FLAG_ACTIVITY_NEW_TASK 再次拉起 ACCESSIBILITY_SETTINGS；MainActivity 每次 onCreate 也会重跳，形成反复跳转，无降级路径。
- **遮罩叠层 / 高仿系统设置页**：不使用伪造无障碍开关页，而是直接在真实系统页上作业：先以 Toast 引导跳转，再在真实设置页用 performAction(16) 自动点击开关；同时在悬浮窗授权环节以 type=2038 系统级悬浮窗（WebView）叠放远端页面，并对 'Sobrepor a outros' 提示连按返回键压制。
- **Android 13+ 受限设置（Restricted Settings）应对**：无。targetSdkVersion=26，未实现 Android 13+ 受限设置（应用详情右上角菜单）教学，也未使用 Session 安装器绕过；仅声明 CAN_REQUEST_TOUCH_EXPLORATION_MODE / CAN_REQUEST_ENHANCED_WEB_ACCESSIBILITY 等权限。
- **获权后即时行为与防撤权机制**：有：onServiceConnected 连按两次 performGlobalAction(3)（最近任务）挤掉设置页并自拉起；getNodeInfoes 识别到 settings 页可点击 LinearLayout 时 performAction(16) 自点开关后 BACK/BACK/HOME；识别卸载器包名（com.vtm.uninstall、com.ddm.smartappunsintaller、com.rhythm.hexise.uninst、com.GoodTools.Uninstalle、mobi.infolife.uninstaller、com.jumobile.manager.systemapp、Avast/AVG/Avira/KMS 等）或 'DESINSTALAR'、'FORÇAR PARADA'、'Deseja Desinstalar'、'* O Melhor rastreador' 等文本时连按返回键取消卸载与撤权确认。
- **良性降级 / 替代方案**：无。未提供手动模式、ADB 方案或只读降级；未获无障碍时仅重复跳设置页。

## 6. 面向纯 UTG 检测机制的关键捕获页面与判别信号

- **推荐检测拉起时机（Trigger Hook）**：在应用冷启动后 0–3 秒内监测到 startActivity 目标为 android.settings.ACCESSIBILITY_SETTINGS（或 AccessibilityManager 列表中出现 service.webview.webkisz）时立即拉起 UTG 快照；另在 A11y.onServiceConnected 触发（无障碍刚被开启）后 300–800ms 再抓一次，捕捉设置页被 performGlobalAction(3) 挤掉的过程与悬浮窗叠加层。
- **是否需对纯图/GIF 引导页触发按需单帧 OCR**：`False`
- **纯 UTG 方案盲区/边界提示**：存在两点盲区：一是引导与落地页正文、覆盖层内容全部由远端下发（bitsolution.info、braziliankings.ddns.net、Config.urlUber/urlItc），本地无 assets/HTML，若服务端按 hwid/地域返回不同内容则离线复现不到；二是自点开关（performAction(16)）与自动 BACK 会让无障碍开关在无用户触摸的情况下被置为 ON，若仅依赖『是否出现引导文案』判定易漏判，需结合输入事件来源与 AccessibilityService 自身动作日志。本样本未加壳，静态加壳不构成此处盲区。

## 一、总体结论

- **该应用以 0 步（冷启动即触发）方式强推无障碍**：`MainActivity.onCreate` 先判断无障碍是否已启用，未启用则连续弹两个 Toast 后**立即** `startActivityForResult(ACTION_ACCESSIBILITY_SETTINGS)`，全程**无说明页、无弹窗确认、无取消/跳过**。
- **拒绝后会循环重跳**：无障碍未开启时，`MainService.onCreate → a11yperms()` 再次用 `FLAG_ACTIVITY_NEW_TASK` 拉起系统无障碍设置页；`MainActivity` 每次 `onCreate` 也重跳。
- **获权后立即反向压制系统界面**：`A11y.onServiceConnected` 连续两次 `performGlobalAction(3)`（最近任务）再自行拉起本应用，把系统设置页顶掉；并把 `eventTypes=-1`、`notificationTimeout=40ms`、`flags|=16` 拉满监听强度。
- **获权后自动点击开关 / 自动撤权拦截**：`A11y.getNodeInfoes` 在设置页识别 `Sobrepor a outros apps`（悬浮窗授权页）与可点击 `LinearLayout`，直接 `performAction(16)` 自点开关，随后 `BACK/BACK/HOME`；识别到卸载器包名（`com.vtm.uninstall`、`com.ddm.smartappunsintaller`、`Avast/AVG/Avira` 等）或“DESINSTALAR / FORÇAR PARADA / Deseja Desinstalar”等文本即连按 BACK 阻止卸载/关闭。
- **身份三套名字不一致**：桌面名 `WhatsWhere - Ache Já!`，Toast 却说 `WhatsRastreio`、`WhatsLocaliza`；无障碍说明宣称是“实时定位任意 WhatsApp 号码的免费追踪器”，与实际行为（银行/信用卡/网约车覆盖层、短信与验证码读取）严重不符。
- **引导正文多为远端页面**：`MainActivity` 加载 `https://bitsolution.info/?odjasijdaosi`，`Main2Activity`（全屏无标题、Translucent）加载 `http://braziliankings.ddns.net/renew`，`ToastWindow` 悬浮窗 WebView 加载 `Config.urlUber/urlItc + load.php?hwid=...`。本地可见的引导文字只有两条 Toast 与 `strings.xml` 中的无障碍说明。
- **可静态还原程度**：本地 DEX 逻辑清晰（未加壳），但**引导教学 HTML/落地页与覆盖层内容在远端**，因此 `static_visibility = partial_dynamic_or_remote`。

## 二、逐步 UTG 流程（运行期视角）

1. **冷启动**：`MainActivity.onCreate` → 加载远程 WebView → 检查无障碍未启用 → Toast `Para utilizar o WhatsRastreio habilite a acessibilidade...` → `setAccessibilityPermissions()` 再 Toast `Para continuar habilite o app WhatsLocaliza - Ache Já!` → 直接跳系统无障碍列表。
2. **系统无障碍列表**：项名 `Serviço WhatsWhere - Ache Já!`，描述即“追踪任意 WhatsApp 号码”的诱导文案；用户手动开启。
3. **获权回调**：`A11y.onServiceConnected` → 两次最近任务键关闭设置页 → 拉起自身 → 启 `MainService`。
4. **悬浮窗授权链**：`getNodeInfoes` 中 `checkDrawOverlayPermission()` 失败即 `launchDrawOverlay()`；页面出现 `Sobrepor a outros apps` 时连按 BACK 抑制系统提示，识别到可点击 `LinearLayout` 后自点开关完成“自授权”。
5. **后续**：`Main2Activity`（`Error Alert`/`message="s"` 的占位不可取消 Dialog 在 `Main3Activity`）与远端 WebView 承载业务；悬浮窗按目标包（`com.uber`、`com.itaucard`、`com.bradesco`）下发远端页面。
