## 5. 让用户完成开启的具体机制与拒权反馈

- **触发时机（Trigger Timing）**：`user_feature_on_demand`
- **是否提供取消/跳过出口**：`False`
- **拒权或返回后的反馈回路**：跳转系统无障碍设置后 1000ms 强制压栈全屏仿设置遮罩；GrantPermissonsActivity$3.run 每 500ms 轮询 BatteryOptimizeService.a()，未开启则持续 postDelayed；从设置页返回触发 GrantPermissonsActivity$2.run → jumpBackFrombackgroundSetting() 立即 startActivity 重建权限中心页，未完成项仍可再次触发同一跳转与压栈，形成“返回即重来”的循环，页面无跳过/取消按钮。
- **遮罩叠层 / 高仿系统设置页**：是。AccessibilityDialogActivity 以 @color/translucent_dark 全屏半透明蒙层覆盖系统无障碍设置页，内部 PermissionToastView 自绘仿系统无障碍列表项（应用图标 + Power Cleaner + Off + toggle_close 假开关 + hand 手指动画 + RecyclerView 5 条假条目），配合 GOT IT 按钮，构成高仿系统设置页的引导层。
- **Android 13+ 受限设置（Restricted Settings）应对**：无（代码中未见 ACTION_APPLICATION_DETAILS_SETTINGS 跳转、未见“允许受限设置”或 Session 安装器相关教学；仅见 ACCESSIBILITY_SETTINGS 与 MANAGE_OVERLAY_PERMISSION 跳转）
- **获权后即时行为与防撤权机制**：有。BatteryOptimizeService.onAccessibilityEvent 监听 com.android.settings 的 InstalledAppDetailsTop / InstalledAppDetailsActivity，通过 createPackageContext 取系统 force_stop 文案并用 findAccessibilityNodeInfosByText + performAction(16) 自动点击，在应用详情页代替用户操作以阻止停止/卸载；同服务还以 typeWindowStateChanged + canRetrieveWindowContent=true 持续读取窗口内容。
- **良性降级 / 替代方案**：无（未提供手动模式、仅观看模式或明确的“暂不开启”降级路径；仅有 dialog_battery_accessibility_layout 的 not_now 用于电池类二次弹窗）

## 结论要点

1. **引导入口在权限中心页，不是冷启动强制弹窗**：用户从导航抽屉进入 [NavigationFragment$1.onClick] 后打开 `GrantPermissonsActivity`（`res/layout/activity_grant_permission`），页面用“安全等级”话术把无障碍包装成三个“待完成项”之一。
2. **三步式引导链**：`initData()` 构造 `Accessibility / Notification Usage / App with Usages` 三行；`updateData()` 通过 `BatteryOptimizeService.a()`、`Settings.canDrawOverlays()` 判定是否已授权；`updateView()` 按已授权数量显示 `In secure / Basic / Full Protection` 与 “Please grant all permissions to enhance security level”。
3. **点击即跳系统无障碍页**：`GrantPermissonsActivity$4.onClick` → `ns.oy.a(Activity,int)` → `startActivityForResult(new Intent("android.settings.ACCESSIBILITY_SETTINGS"))`，随后 `postDelayed(..., 1000L)` 埋下压栈动作。
4. **1 秒后向系统设置页压全屏遮罩**：`GrantPermissonsActivity$4$1.run` → `showAccessibilityToast()` → 启动 `AccessibilityDialogActivity`（`setContentView(R.layout.accessibility_toast_view)`），根布局是 `com.antivirus.power.cleaner.v.PermissionToastView`，`@color/translucent_dark` 全屏半透明蒙层 + 仿无障碍列表项（应用图标 + `Power Cleaner` + `Off` + `@drawable/toggle_close` 假开关 + `@drawable/hand` 手指动画 + RecyclerView 5 条假条目），文本 “To prevent apps from restarting and save battery power, please find and enable Power Cleaner.”，唯一按钮 `GOT IT`。
5. **拒权循环**：`GrantPermissonsActivity$3.run` 每 500 ms 轮询 `BatteryOptimizeService.a()`，未开启则持续 `postDelayed`；`GrantPermissonsActivity$2.run`/`jumpBackFrombackgroundSetting()` 返回即重建 `GrantPermissonsActivity`，再次进入同一跳转+压栈流程，页面无“跳过/取消”路径。
6. **获权后用于对抗卸载**：`BatteryOptimizeService.onAccessibilityEvent` 监听 `typeWindowStateChanged`，仅处理 `com.android.settings`，命中 `InstalledAppDetailsTop`/`InstalledAppDetailsActivity` 时用 `createPackageContext("com.android.settings")` 取 `force_stop` 文案，`findAccessibilityNodeInfosByText` + `performAction(16)` 自动点击，属获权后的“防卸载/自动点确认”动作。
7. **身份层**：默认 `app_name=Power Cleaner`，但 `values-es/fr/pt/ru/hi/vi/ja…` 的 `app_name` 为 `Bloqueo de pantalla` / `Écran de verrouillage` / `Блокировка экрана` / `Khóa Màn hình` / `स्क्रीन लॉक` / `ScreenLock`，按语言切换成“屏幕锁”，与清理工具宣称不一致；无障碍说明还写明 “You can have the privacy warning ignored.”，教用户忽略系统警告。
8. **静态可见性**：完全静态可还原（无加壳），`ACCESSIBILITY_SETTINGS` 为硬编码常量而非 Manifest 跳转点，`ACTION_APPLICATION_DETAILS_SETTINGS`/受限设置（Android 13+）教学**未出现**（`targetSdk` 对应 2018 年体系）。
