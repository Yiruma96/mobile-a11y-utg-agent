## 分析结论（代码级定向核验）

**样本定位**：初始路径 `...\r2_riltok\input.apk` 已不存在，我改用同一 family/包名的在野样本 `0497b600…e2a98.apk`（package `com.aviasalea`，label `Aviasales`，targetSdk 19），核验结果与预筛线索完全一致（无障碍类 `com.aviasalea.srs.GPSrs`、label `Google Services`、无 `android:description`）。

**引导链路（纯运行期 UTG 视角）**

1. **冷启动 0 步**：`MainActivity.onCreate` 在透明主题（`Theme.Translucent.NoTitleBar`）下 `setContentView` 后立刻 `startCommandService()`、用原生 `Realtalk.getStartWebUrl()` 的远端地址打开 `WbActivity`，随即 `finish()` —— 桌面图标点开即消失，无任何可感知界面，纯一阶段远端 WebView 外壳。
2. **后台定时死循环拉起引导页**：`com.aviasalea.srs.StDlgSrs.onStartCommand` → 新线程 → `Timer.schedule(task, 0, TIMER)`；`StDlgSrs$StartDialogAccessTimerTask.run` 每周期判断 `ASTls.isAccessibilitySettingsOn(context)`，**未开启就无条件 `IntTls.startDialogAccess()`** 重新拉起 `com.aviasalea.ds.StartDialog`。这就是"拒绝/返回设置页后仍反复弹出"的机制来源。
3. **引导弹窗（原生 Activity + 不可取消 AlertDialog）**：`StartDialog.onCreate` → `showDialog()`，`setCancelable(false)`、`setCanceledOnTouchOutside(false)`，标题 `Attention`，正文 = `start_dialog_description` + 空格 + `accessibilityservice_label`，即「Unfortunately Google Play Services has stopped. For the correct operation of the device select a line in the menu and self-enable: **Google Services**」，**只有一个 OK 按钮，无取消/跳过**。
4. **跳受限设置**：唯一 OK 按钮 `StartDialog$1.onClick` 里 `isAccessibilitySettingsOn` 为假时 `startActivity(new Intent("android.settings.ACCESSIBILITY_SETTINGS"))` 并关闭弹窗——直接落到系统无障碍列表，列表项显示的正是伪装的 `Google Services`（`res/values/strings.xml:15`），配置 `res/xml/service_conf.xml` 未写 description，用户只能看到这个伪造标签。
5. **获权后动作**：`GPSrs.onServiceConnected()` 立刻 `onBack()`（`IntTls.minimizeApp` → HOME Intent 自我最小化，避免停留在设置页被发现），并 `setServiceInfo` 置 `eventTypes=-1`（全事件）、`flags=17`、`notificationTimeout` 全量监听。

7. **相邻引导（同族同一套 UI 手法）**：`GPSrs.adReq` → `startAdminRequest` 拉起 `AdRequestDialog`（Manifest 中 `android:process="com.googleplay.activities.AdminRequestDialog"`，label `Play Market`）；`GPSrs.nlService` → `startNLSettings` 跳通知使用权设置。
